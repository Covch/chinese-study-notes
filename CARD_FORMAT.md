# Формат карточек (контракт viewer ↔ filler_bot)

Этот файл — единый источник правды для обоих проектов. Изменения формата нужно
синхронизировать между `git_web` (viewer) и `filler_bot` (бот).

## Расположение

```
git_web/                 <- корень репозитория (GitHub Pages)
├── index.html           <- viewer
├── css/, js/            <- код viewer'а
└── cards/               <- карточки (md-заметки)
    ├── index.json       <- индекс всех карточек
    ├── hieroglyph-你好.md
    └── rule-的.md
```

## Файл карточки

Одна карточка = один `.md` файл в `cards/`.

Имя файла: `<type>-<sanitized-title>.md`, где `sanitized-title` — заголовок, в
котором пробелы и знаки пунктуации заменены на `-`, ASCII-буквы приведены к
нижнему регистру. Unicode-буквы (китайские, кириллица) сохраняются как есть,
т.к. это и есть «понятный вид». Примеры: `hieroglyph-你好.md`, `rule-的.md`.

Если файл с таким именем уже существует — к имени добавляется суффикс `-2`,
`-3`, ... (коллизия не перезаписывает существующую карточку).

### Структура

YAML-frontmatter (служебные поля) + тело с секциями `## Поле` (контент карточки).

Служебные поля frontmatter:

| поле    | тип    | обязательное | описание                                              |
|---------|--------|--------------|-------------------------------------------------------|
| `title` | string | да           | Название карточки (вводится вручную)                  |
| `type`  | string | да           | `hieroglyph` или `rule`                               |
| `lesson`| int    | да           | Номер урока                                           |
| `level` | string | да           | Уровень, свободный текст (`HSK1`, `HSK3.0`, ...)      |

**Поля, связанные с пользователем (когда смотрел, как оценил), в md НЕ хранятся** —
только в `localStorage` браузера.

### Карточка «Иероглиф»

Секции тела (в этом порядке):

```markdown
---
title: Приветствие 你好
type: hieroglyph
lesson: 1
level: HSK1
---

## Иероглиф

你好

## Пиньинь

nǐ hǎo

## Перевод

привет; здравствуйте

## Пример

你好，我叫李明。
```

### Карточка «Правило»

Секции тела (в этом порядке):

```markdown
---
title: Частица 的
type: rule
lesson: 2
level: HSK1
---

## Правило

Частица 的 ставится между определением и определяемым словом.

## Примеры

我的书 — моя книга
老师的名字 — имя учителя
```

### Правила рендеринга

1. Всё, что идёт после `## Заголовок` и до следующего `##`, — содержимое одного поля
   (многострочное, переносы строк сохраняются).
2. Каждая секция `## ...` — **один спойлер**: при открытии карточки все поля закрыты,
   заголовок секции виден как подпись кнопки-спойлера, содержимое скрыто.
3. `title`, `lesson`, `level` видны всегда (шапка карточки), спойлерами не закрываются.
4. Текст между frontmatter и первой секцией `##`, если он есть, показывается как
   обычный текст над спойлерами (по возможности не использовать).
5. Секция с пустым содержимым показывается как спойлер с пометкой «пусто».

## Индекс `cards/index.json`

Единственный способ для viewer'а узнать список карточек (GitHub Pages не отдаёт
листинг директории). Порядок элементов = порядок добавления карточек.

```json
{
  "version": 1,
  "cards": [
    {
      "path": "cards/hieroglyph-你好.md",
      "title": "Приветствие 你好",
      "type": "hieroglyph",
      "lesson": 1,
      "level": "HSK1"
    }
  ]
}
```

- `path` — путь относительно корня репозитория, без URL-кодирования (viewer сам
  кодирует сегменты через `encodeURI`).
- Дубликаты `path` в индексе не допускаются.
- Индекс обновляет бот при добавлении/удалении карточек. Ручное добавление карточки
  требует ручного обновления `index.json` (см. `tools/build_index.py`).

## Пользовательский прогресс (localStorage, только viewer)

| ключ                 | содержимое                                              |
|----------------------|---------------------------------------------------------|
| `cl:v1:user`         | `{"name": "..."}`                                       |
| `cl:v1:progress`     | `{"<path>": [{"ts": 1699999999, "rating": "good"}]}`    |

`rating`: `bad` (не помню) | `ok` (помню нормально) | `good` (помню хорошо).
Хранится весь массив оценок (не только последняя), элементы дописываются в конец.
