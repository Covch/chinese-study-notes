# Помощник по изучению китайского языка

Создан с помощью DeepSeek.

Статический сайт-показчик карточек для изучения китайского: список карточек и
экран карточки, где каждое поле закрыто спойлером (сам выбираешь, с какой
стороны повторять). Названий у карточек нет: подпись «Иероглиф 7» / «Правило 2»
строится по типу и порядку в индексе, чтобы не подсказывать ответ.

Формат карточек описан в [CARD_FORMAT.md](CARD_FORMAT.md) — это контракт,
синхронный с логикой наполнения.

## Структура

```
index.html          viewer
glyphs.html         сетка всех иероглифов
css/style.css       оформление (тёмная тема)
js/md.js            парсер карточек (frontmatter + секции "## ...")
js/srs.js           интервальное повторение и слияние данных (чистые функции)
js/store.js         localStorage/sessionStorage и кэш серверного режима
js/pagination.js    постраничный вывод (чистые функции)
js/cardlabel.js     подпись карточки по типу и номеру (чистые функции)
js/api.js           клиент HTTP API (fetch, ошибки, валидация черновика карточки)
js/comments.js      комментарии: список, форма с картинками, проверки файлов
js/app.js           логика: список, карточка, повторение, данные, статистика, вход
js/glyphs.js        сетка иероглифов: фильтры и ссылки на карточки
tools/build_index.py  пересборка cards/index.json
tools/test_js.js    тесты js/*.js (запуск через gjs)
cards/              карточки (.md) и индекс index.json
```

## Два режима работы

Сайт умеет работать без бэкенда и с сервером; режим определяется автоматически
запросом `GET api/health` (таймаут 2 секунды).

- **Серверный режим** (`{"app":"chinese-cards"}`) — вход по логину и паролю,
  карточки, прогресс и комментарии приходят с сервера. Появляются вкладки
  «Добавить» (создание карточки в репозитории на сервере) и «Статистика»
  (цифры, график за 30 дней, распределение оценок, таблица лидеров), а в шапке —
  имя пользователя и «Выйти». Если в браузере остался старый прогресс, сайт
  предложит безопасно перенести его на сервер (слияние, без потери истории).
- **Fallback** (GitHub Pages, локальный `python3 -m http.server`, `/api/health`
  недоступен) — всё как раньше: прогресс и имя в `localStorage`, экспорт/импорт
  JSON, SRS в браузере. Вход, комментарии, создание карточек и серверная
  статистика скрыты.

Прямые ссылки: `#card=...` — карточка, `#review` — повторение, `#data` — данные.
В серверном режиме ещё `#add` и `#stats`. API и форматы данных описаны в
`docs/server-contract.md` рядом с исходниками сервера.

## Запуск с сервером

1. Соберите и запустите `chinese-cards-server` (например,
   `chinese-cards-server serve -web ../git_web -data ./data`) — подробности
   запуска, HTTPS и пользователей см. в `docs/deploy.md` в исходниках проекта.
2. Откройте адрес сервера (по умолчанию `http://127.0.0.1:8090/`) и войдите
   пользователем, созданным через `chinese-cards-server user add`.
3. Страницу не нужно открывать через `file://`: статика и карточки должны
   отдаваться одним origin.

Без сервера для локального просмотра достаточно:

```sh
cd git_web
python3 -m http.server 8123
# затем http://localhost:8123/
```

`fetch` к `cards/*.md` не работает на `file://`, поэтому открывать нужно по http.

## Как добавить карточку руками

1. Создайте файл `cards/<type>-<номер>.md` по формату из
   [CARD_FORMAT.md](CARD_FORMAT.md) (frontmatter `type`, `lesson`, `level` +
   секции `## Заголовок`). Номер — первый свободный для этого типа; название
   не пишется, чтобы не подсказывать содержимое.

2. Пересоберите индекс:
   
   ```sh
   python3 tools/build_index.py
   ```
   
   Скрипт пересканирует `cards/*.md`, сохранит порядок уже известных путей и
   допишет новые в конец. Сторонних пакетов не требует (только stdlib).

3. Обновите страницу в браузере.

## Сетка иероглифов

Страница [`glyphs.html`](glyphs.html) показывает все карточки `type: hieroglyph`
квадратной сеткой: внутри квадрата — сам иероглиф, по клику открывается его
карточка в viewer'е. Правила в сетку не попадают. Фильтры — урок, уровень и поиск
по иероглифу или пиньиню (пиньинь ищется без учёта тонов: `ni` находит `nǐ`).

Символ берётся из секции `## Иероглиф` соответствующего `.md`, поэтому страница
читает карточки после загрузки `cards/index.json`. Сетка выводится постранично
(60 плиток на страницу). Список карточек на главной тоже постраничный (20 на
страницу); при смене фильтров страница сбрасывается на первую.

## Повторение

Три вкладки: **Список** (каталог с фильтрами), **Повторение**, **Данные**.
Сетка иероглифов — отдельная страница (ссылка «Иероглифы» в ряду вкладок).

На вкладке «Повторение» выбираются фильтры (урок, уровень, тип) и количество карточек,
а режим — один из двух:

- **Пора повторить** — упрощённый SM-2: сначала идут просроченные карточки (по сроку),
  затем новые. Оценки «Не помню» (клавиша `1`), «Слабо помню» (`2`), «Хорошо помню» (`3`).
  «Не помню» возвращает карточку в конец этой же сессии, но не больше двух раз.
- **Подряд по фильтрам** — просто по порядку индекса, без интервалов. Годится, чтобы
  пройти урок целиком.

Начатая сессия переживает перезагрузку страницы: её можно продолжить кнопкой
«Продолжить начатую». Прогресс сессии лежит в `sessionStorage`.

Алгоритм и формулу правки «легкости» см. в [CARD_FORMAT.md](CARD_FORMAT.md).

## Пользовательские данные и резервная копия

В fallback-режиме прогресс, расписание повторений и имя хранятся только в браузере
(`localStorage`: `cl:v1:user`, `cl:v1:progress`, `cl:v1:srs`). В серверном режиме
они живут на сервере (в памяти страницы остаётся только кэш для синхронного
чтения), а в `localStorage` сайт их не пишет.

Вкладка «Данные» показывает сводку и умеет:

- **выгрузить** всё в JSON-файл (`chinese-cards-ГГГГ-ММ-ДД.json`; в серверном
  режиме — тем же форматом через `/api/export`);
- **загрузить** файл: «объединить» (ничего не теряет, безопасный режим) или
  «заменить» (с подтверждением; в серверном режиме — через API импорта);
- **сбросить расписание** повторений, не трогая историю оценок;
- в серверном режиме — сменить имя и пароль.

Копию удобно переносить между браузерами и хранить как страховку: очистка данных
сайта в браузере стирает локальный прогресс безвозвратно.

## Тесты

Математика повторения, слияние копий, хранилище, клиент API, проверки
комментариев и валидация карточки покрыты тестами в `tools/test_js.js`.
Запускаются движком SpiderMonkey (`gjs`), Node не обязателен:

```sh
cd git_web
gjs tools/test_js.js        # код возврата ≠ 0, если есть провалы
```

Если Node установлен, тот же файл работает и через `node tools/test_js.js`.

Группа общих SRS-векторов читает `../shared/srs_vectors.json`, который лежит в
корне проекта рядом с `git_web`. В самостоятельном клоне `git_web` этого файла
нет — группа честно пропускается с пометкой «пропущено»; полный прогон (638
проверок) — только из корня проекта.

Тесты проверяют `js/srs.js`, `js/md.js`, `js/store.js` (включая серверный кэш),
`js/cardlabel.js`, `js/api.js`, `js/comments.js`, синтаксис `js/app.js` и
совпадение id из `app.js` с разметкой `index.html`. Интерфейс, сеть и переходы
по кнопкам тестами не покрыты — их проверяет человек в браузере.
